1. Grundprinzip

Du brauchst kein PHP zu können. Du beschreibst was du willst — Claude Code baut es.

TeilWas du angibstBeispiel
SeiteName und RouteName: Kundenliste, Route: /kunden
DatenEndpunkt + Felder + SortierungEndpunkt: adressen/getAdressen
DarstellungTabelle, Formular, PaginationSeite mit Tabelle und Pagination
✓
Claude Code liest beim Start automatisch CLAUDE.md — alle Regeln sind dort hinterlegt. Du musst sie nicht wiederholen.

2. Seitentypen

Der Begriff im Prompt bestimmt was Claude Code anlegt.

Begriff im PromptWas entstehtWann verwenden
SeiteEinfache Seite ohne TabelleDashboards, Detailansichten
Seite mit TabelleListe als Bootstrap-TabelleListen ohne Blättern
Seite mit Tabelle und PaginationListe mit BlätternGroße Datenmengen
Formular oder EingabemaskeSeite mit EingabefeldernErfassen, Bearbeiten
⚠
Kein Formular angeben wenn du nur eine Liste willst.
Kein Pagination angeben wenn du keine Blätterfunktion brauchst.

3. Einfache Liste

Der minimale Prompt für eine Datenliste.

Minimaler Prompt

-- Einfachste Form Lege eine Seite mit Tabelle an. Name: Kundenliste Route: /kunden Endpunkt: adressen/getAdressen Felder: kennziffer, name2, name1, ort Sortierung nach name2.

Mit Pagination

Lege eine Seite mit Tabelle und Pagination an. Name: Kundenliste Route: /kunden Endpunkt: adressen/getAdressen Felder: kennziffer, name2, name1, ort Sortierung nach name2. 20 Eintraege pro Seite.

Mit Filter

Lege eine Seite mit Tabelle an. Name: Einsatzliste Route: /einsatz Endpunkt: dispo/getEinsatzFiltered Felder: nr, von, bis, bezeichnung, fahrer1 Sortierung nach von. Filter: von (Datum), bis (Datum) -- Default: Anfang und Ende des aktuellen Monats. Button "Heute" setzt von und bis auf das heutige Datum.

Der Pfad vor dem Endpunkt-Namen entspricht dem Controller in RATIOserver — er weicht manchmal vom Tabellennamen ab.

EINSATZweicht ab: dispodispo/getEinsatz
RECHNUNG= Tabellennamerechnung/getRechnungen

Bei Unsicherheit welcher Pfad gilt: Rolf fragen.

5. Pfeil-Notation — Mehrere Datasets

Wenn du Daten aus mehreren Tabellen auf einer Seite brauchst, beschreibst du die Beziehung mit Pfeilen. Claude Code baut das Mapping automatisch — du schreibst kein PHP.

Die drei Pfeile

NotationBedeutungWann verwenden
A.FREMDKEY -> B.KEY Jeder Satz in A hat genau einen Satz in B Lookup auf kleine Tabelle (Länder, Status, Kategorien)
A.FREMDKEY ->* B.KEY Jeder Satz in A hat genau einen Satz in B Lookup auf große Tabelle (Kunden, Artikel, Mitarbeiter)
A.KEY <- B.FREMDKEY Jeder Satz in A hat mehrere Sätze in B Detailpositionen, Unterpositionen (1:N)

Wann → und wann →* ?

Lookup-TabelleBeispielePfeil
Klein / überschaubarLänder, Status, Kategorien, Währungen→
Groß (viele Tausend Sätze)Kunden, Artikel, Mitarbeiter, Lieferanten→*
ℹ
Faustregel: Wenn die Tabelle im Laufe der Zeit sehr groß werden kann — →* verwenden.

Pfeile können verkettet werden

-- Bedeutung: B ist der zentrale Dataset -- A hängt per 1:N an B (Positionen) -- C wird per N:1 Lookup aufgelöst (Kunde) A <- B.FREMDKEY ->* C.KEY

6. Beispiele Pfeil-Notation

Beispiel 1 — Einfacher Lookup →

Rechnungen mit Statustext — Statustabelle ist klein:

Lege eine Seite mit Tabelle an. Name: Rechnungsliste Route: /rechnungen Abfrage 1 -- Dataset: rechnungen: Endpunkt: rechnung/getRechnungen Felder: renr, statusid, betrag, datum Sortierung nach datum. Abfrage 2 -- Dataset: status: Endpunkt: rechnungsstatus/getRechnungsstatus Felder: id, bezeichnung Verknuepfung: RECHNUNG.STATUSID -> STATUS.ID

Beispiel 2 — Lookup auf große Tabelle →*

Rechnungen mit Kundenname — Kundentabelle hat viele Tausend Sätze:

Lege eine Seite mit Tabelle an. Name: Rechnungsliste Route: /rechnungen Abfrage 1 -- Dataset: rechnungen: Endpunkt: rechnung/getRechnungen Felder: renr, kundenid, betrag, datum Sortierung nach datum. Abfrage 2 -- Dataset: kunden: Endpunkt: adressen/getAdresseById Felder: kennziffer, name2 Verknuepfung: RECHNUNG.KUNDENID ->* KUNDE.KENNZIFFER

Beispiel 3 — Detailpositionen ←

Rechnung mit allen zugehörigen Positionen:

Lege eine Seite an. Name: Rechnungsdetail Route: /rechnungen/detail Abfrage 1 -- Dataset: rechnung: Endpunkt: rechnung/getRechnungById Felder: renr, datum, betrag, kundenid Abfrage 2 -- Dataset: positionen: Endpunkt: rechnung/getPositionen Felder: posnr, renr, artikel, menge, preis Sortierung nach posnr. Verknuepfung: RECHNUNG.RENR <- POSITIONEN.RENR

Beispiel 4 — Verkettet (1:N + N:1)

Rechnungen mit Positionen UND Kundenname:

Lege eine Seite an. Name: Rechnungsuebersicht Route: /rechnungen/uebersicht Abfrage 1 -- Dataset: rechnungen: Endpunkt: rechnung/getRechnungen Felder: renr, kundenid, betrag, datum Sortierung nach datum. Abfrage 2 -- Dataset: kunden: Endpunkt: adressen/getAdresseById Felder: kennziffer, name2 Abfrage 3 -- Dataset: positionen: Endpunkt: rechnung/getPositionen Felder: posnr, renr, artikel, menge, preis Sortierung nach posnr. Verknuepfung: POSITIONEN <- RECHNUNG.KUNDENID ->* KUNDE.KENNZIFFER

Beispiel 5 — Mehrere unabhängige Lookups

Einsatzplan: Fahrzeug und Fahrer kommen aus separaten Tabellen:

Lege eine Seite mit Tabelle an. Name: Einsatzplan Route: /einsatz Abfrage 1 -- Dataset: einsaetze: Endpunkt: dispo/getEinsatz Felder: nr, von, bis, fahrzeugid, fahrerid Sortierung nach von. Abfrage 2 -- Dataset: fahrzeuge: Endpunkt: fahrzeuge/getFahrzeuge Felder: id, kennzeichen, typ Abfrage 3 -- Dataset: fahrer: Endpunkt: personal/getPersonal Felder: id, name, vorname Verknuepfung: EINSATZ.FAHRZEUGID -> FAHRZEUGE.ID EINSATZ.FAHRERID -> FAHRER.ID

7. /select — Direkter SQL-Zugriff

Wenn kein passender Endpunkt existiert, kannst du einen fertigen SQL übergeben.

✗
Du schreibst den SQL komplett selbst — Claude Code verändert ihn nicht und generiert keinen SQL.

Parameter-Notation

NotationQuelleBeispiel
:[GET.param]URL: ?id=123:[GET.id]
:[POST.param]Formular-Feld:[POST.status]
:[datasetname.feld]Ergebnis vorheriger Abfrage:[kunde.kennziffer]
:["wert"]Fester Wert:["DE"]

Einfach — ohne Parameter

Lege eine Seite mit Tabelle an. Name: Auswertung Route: /auswertung Abfrage 1 -- Dataset: ergebnis: Endpunkt: /select SELECT nr, bezeichnung, sum(betrag) AS summe FROM auftraege GROUP BY nr, bezeichnung

Mit allen Parameter-Typen

Lege eine Seite an. Name: Kundenauftraege Route: /kundenauftraege Abfrage 1 -- Dataset: kunde: Endpunkt: /select SELECT kennziffer, name1, name2 FROM adressen WHERE kennziffer = :[GET.id] Abfrage 2 -- Dataset: auftraege: Endpunkt: /select SELECT auftrnr, datum, betrag, status FROM auftraege WHERE kundenid = :[kunde.kennziffer] AND land = :["DE"] AND status = :[POST.status]
